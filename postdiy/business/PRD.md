## 第一部分：产品定位分析

### 1.1 产品解决什么问题

实体商家（餐饮、零售、服务）在日常经营中频繁遇到客流少、营业额下降、利润低、员工难管等问题，但绝大多数老板：

- **没有时间**系统学习商业知识
- **不知道怎么描述**自己的问题（无法精确提问）
- **找不到针对性方案**（搜索结果太泛，不落地）
- **看完也不会做**（缺少可执行的行动步骤）

本产品解决的核心痛点：**让不会提问的老板，通过几次点击，获得可立即执行的经营解决方案。**

### 1.2 用户为什么需要它

| 用户现状 | 本产品的价值 |
|---------|------------|
| 知道有问题但说不清是什么问题 | 点击式选择，无需文字输入即可定位问题 |
| 搜索结果泛而不精 | 基于行业+阶段+症状的三维精准匹配 |
| 看了文章不知道怎么做 | 每个方案附带「今日执行任务」和「7天改善计划」 |
| 请顾问太贵，自学太慢 | 免费/低成本，3分钟获得诊断结果 |
| 问题反复出现无法根除 | 给出原因排序，从根因到表象逐层拆解 |

### 1.3 与普通知识网站的区别

| 维度 | 普通知识网站 | 本产品 |
|------|------------|--------|
| 交互方式 | 用户输入关键词搜索 | 用户点击选择，系统引导诊断 |
| 内容结构 | 按知识体系分类（营销/管理/财务） | 按问题场景分类（没客流/利润低/员工难管） |
| 输出结果 | 一篇文章 | 诊断结果 + 原因排序 + 解决方案 + 执行任务 + 7天计划 |
| 使用门槛 | 需要用户能准确描述问题 | 只需点击选择，3步完成诊断 |
| 行动性 | 看完不知道做什么 | 每步都有明确执行动作 |
| 用户路径 | 搜索→阅读→自行提炼 | 选择→诊断→方案→执行 |

## 第二部分：用户使用流程设计

### 2.1 核心使用流程（主路径）

```
打开首页
  │
  ▼
【第1步】选择核心问题（首页）
  "你的店现在遇到什么问题？"
  ┌──────────┬──────────┬──────────┐
  │ 没有客流  │ 营业额下降 │ 利润太低  │
  ├──────────┼──────────┼──────────┤
  │ 员工管理难 │ 顾客流失   │ 竞争压力大 │
  ├──────────┼──────────┼──────────┤
  │ 不会做营销 │ 其他问题   │          │
  └──────────┴──────────┴──────────┘
  │
  ▼
【第2步】选择行业类型
  "你的店属于哪个行业？"
  ┌────────┬────────┬────────┬────────┐
  │  餐饮   │  零售   │  服务业  │  其他  │
  └────────┴────────┴────────┴────────┘
  │
  ▼
【第3步】选择经营阶段
  "你的店开了多久？"
  ┌──────────┬────────────┬────────┐
  │ 新店(<3月) │ 成长期(3-12月) │ 老店(>1年) │
  └──────────┴────────────┴────────┘
  │
  ▼
【第4步】选择具体症状（多选）
  "具体是哪种情况？（可多选）"
  根据第1步的问题类型动态展示不同选项
  │
  ▼
【第5步】查看诊断结果页
  ┌─────────────────────────────┐
  │  1. 问题判断                 │
  │  2. 可能原因排序（按可能性）    │
  │  3. 解决方案（2-3套）         │
  │  4. 今日执行任务（1-3件）      │
  │  5. 7天改善计划               │
  │  6. 成功案例                  │
  │  7. 相关工具模板              │
  └─────────────────────────────┘
  │
  ▼
【第6步】执行与收藏
  - 收藏方案 → 个人中心查看
  - 下载工具模板 → 立即使用
  - 分享给同行
```

### 2.2 快捷路径

除主路径外，提供快捷入口：

- **热门问题直达**：首页展示TOP5热门问题，点击直接进入诊断
- **行业专区入口**：餐饮专区/零售专区/服务专区，按行业浏览问题
- **搜索入口**：支持关键词搜索问题（辅助入口，非主路径）

### 2.3 流程设计原则

| 原则 | 说明 |
|------|------|
| 零输入原则 | 核心流程中不要求用户输入任何文字，全部通过点击完成 |
| 3步诊断原则 | 从打开到获得诊断结果，核心步骤不超过4次点击 |
| 渐进揭示原则 | 每步只展示当前需要的选择，不一次展示所有信息 |
| 即时反馈原则 | 每次选择后立即有视觉反馈，让用户知道"系统在帮我分析" |
| 可回退原则 | 任何步骤都可以返回上一步重新选择 |

## 第四部分：核心功能模块设计

### 4.1 问题诊断系统

**核心逻辑**：基于用户选择的「问题类型 + 行业 + 阶段 + 症状」四维组合，匹配知识库中的诊断路径，输出结构化诊断结果。

**诊断流程配置**：

```
问题类型（8大类）
  └── 行业适配（餐饮/零售/服务/通用）
       └── 经营阶段适配（新店/成长期/老店）
            └── 具体症状（2-6个可多选选项）
                 └── 诊断路径匹配
                      ├── 问题判断（1条）
                      ├── 原因排序（2-4条，按可能性降序）
                      ├── 解决方案（2-3套，分优先级）
                      │    ├── 方案名称
                      │    ├── 方案描述
                      │    ├── 预期效果
                      │    ├── 执行难度（简单/中等/较难）
                      │    └── 预计见效时间
                      ├── 今日执行任务（1-3件）
                      ├── 7天改善计划
                      │    ├── Day1 任务
                      │    ├── Day2 任务
                      │    ├── ...
                      │    └── Day7 任务
                      ├── 推荐案例（1-2个）
                      └── 推荐工具模板（1-3个）
```

**症状选项动态展示规则**：

| 问题类型 | 症状选项示例 |
|---------|------------|
| 没有客流 | 路过的人少 / 有人看但不进店 / 进店不消费 / 老客户减少 / 周边没有目标客群 |
| 营业额下降 | 客单价低 / 复购率低 / 旺季不旺 / 闲时太空 / 忙时服务跟不上 |
| 利润太低 | 成本太高 / 定价不合理 / 损耗浪费大 / 促销过度 / 隐性成本多 |
| 员工管理难 | 招不到人 / 留不住人 / 积极性差 / 服务态度差 / 培训不到位 |
| 顾客流失 | 投诉增多 / 回头客少 / 差评增多 / 会员不活跃 / 顾客转竞争对手 |
| 竞争压力大 | 周边新开同类店 / 对手价格更低 / 对手活动更多 / 差异化不够 |
| 不会做营销 | 不知道怎么做活动 / 活动效果差 / 线上不会做 / 预算有限 / 没时间做 |
| 其他问题 | 位置不好 / 房租太高 / 供应链问题 / 合规问题 / 转型困难 |

### 4.2 知识解决方案库

## 第五部分：知识库结构设计

### 5.1 核心设计原则

**不按知识体系分类，按问题场景组织。**

传统知识库：营销学 → 定价策略 → 渗透定价  
本产品知识库：利润太低 → 可能原因：定价不合理 → 解决方案：重新定价

### 5.2 知识链路结构

```
问题场景 (Problem)
  │
  ├── 原因 (Cause)
  │    ├── 判断方法（如何确认是这个原因）
  │    ├── 判断问题（向用户提问来确认）
  │    └── 可能性权重（排序依据）
  │
  ├── 解决方案 (Solution)
  │    ├── 方案详情
  │    ├── 执行步骤
  │    ├── 今日任务
  │    ├── 7天计划
  │    └── 注意事项
  │
  ├── 执行动作 (Action)
  │    ├── 动作名称
  │    ├── 动作描述
  │    ├── 预计耗时
  │    └── 所需资源
  │
  └── 案例 (Case)
       ├── 案例背景
       ├── 执行过程
       └── 效果数据
```

9. 商场里客流被截流

12. 天气差就没人来
13. 促销时有人不促销没人

**营业额下降（13个）**

9. 套餐利润太薄
