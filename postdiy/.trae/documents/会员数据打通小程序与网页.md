# 会员体系打通：小程序 ↔ 网页（腾讯云 CloudBase）

## Context

网页版海报编辑器已有完整会员体系：手机号+短信注册、手机号+密码登录、会员个人信息（商家名称/促销文案/logo/二维码）云端同步（CloudBase `users` 集合 + 七牛图片 CDN）。小程序版目前只有本地存储的商家数据（`postdiy_mini_business`）和未接通的电话骨架（login 页 UI 已有、`wx-login` 轻量账号云函数已写好但未部署打通）。

**目标**：同一手机号账号在网页和小程序任意一端登录，会员个人信息完全一致，任意一端修改都保存到腾讯云并同步到另一端。

## 已确认的关键事实

- 网页 API 网关：`https://api.peacelove.top/{云函数名}`（POST JSON，返回 `{success, message, data}`，CORS `ACAO:*`）
- 云函数输入已兼容双格式（HTTP `event.body` 字符串 / 小程序直调 `event.xxx`）；**输出**只有 HTTP 包装格式 `{statusCode, headers, body: JSON字符串}`（`wx-login` 除外，它返回 `{code, message, data}`）
- `users` 集合身份字段：`phone`/`password`/`hasPassword`/`miniOpenid`；VIP 字段：`vipValidUntil`（手机号账号）/`vipExpire`（轻量账号，字段不统一）；业务字段：`brandname`/`promoText`/`logoUrl`/`qrcodeUrl`/`logoTransparent` 等
- 小程序 `services/cloud.ts`：weapp 假设 `{code,message,data}` 格式（调 `login-with-password` 等会挂）；H5 走 mock 完全未接真实云端
- 小程序 business 字段 ↔ 云端映射：`name↔brandname`、`promoText↔promoText`、`logoSrc↔logoUrl`、`qrcodeSrc↔qrcodeSrc`、`logoStyle('original'⇔true/'rounded'⇔false)↔logoTransparent`；小程序特有 `nameColor`/`logoStyle`/`logoScaleByTemplate` 云端暂无字段
- 图片必须经 `user-update-image-qiniu`（base64 → 七牛 URL）换远程 URL，否则跨端无法显示；小程序端七牛图已验证可用（no-referrer + CORS）

## 实施方案

### A. 云函数修改（4 个，改完需部署到 env `postdiy-0g2mftaf6a0fc450`）

1. **`cloudfunctions/login-with-password/index.js`**
   - 登录成功后：若 `cloud.getWXContext().OPENID` 存在（小程序端调用自带）→ 先把其它记录上同 `miniOpenid` 清空（防多记录冲突），再写入本记录完成绑定
   - 返回 `data` 增加 `brandname`/`promoText`（logoUrl 等已有）
2. **`cloudfunctions/user-register/index.js`**（短信注册/登录）
   - 注册成功后同上绑定 `miniOpenid`（小程序新用户注册即与微信绑定）
   - 返回 `data` 对齐 user-get-info 的业务字段
3. **`wechat-mini/cloudfunctions/wx-login/index.js`**
   - `vipExpire` 改为从 `vipValidUntil` 推导（兼容旧 `vipExpire` 字段）→ 修复绑定手机号账号后 VIP 状态显示错误
   - `miniOpenid` 命中多条时优先有 `phone` 的记录
   - 返回增加 `phone`/`isVip`
4. **`cloudfunctions/user-get-info/index.js` + `cloudfunctions/user-update-info/index.js`**
   - 各增加 `nameColor`/`logoStyle`/`logoScaleMap`（JSON 字符串）三个字段读写；`undefined` 不更新，向后兼容（网页端不读不写，无影响）

### B. 小程序 services 层

1. **重写 `wechat-mini/src/services/cloud.ts`**
   - weapp：`Taro.cloud.callFunction` → 结果归一化：`body` 字符串 JSON.parse 后取 `data`（success=false 抛错）／`code` 格式直取／兜底直接返回
   - H5：`fetch('https://api.peacelove.top/' + name)` POST JSON → `{success,message,data}`，统一返回 `data`，失败 throw（替换现有 mock import）
2. **新建 `wechat-mini/src/services/sync.ts`**（对齐网页 `cloud-sync.js`）
   - `pullBusinessInfo(userId)` → user-get-info → 映射为 `BusinessInfo`（含 logoTransparent↔logoStyle、logoScaleMap JSON 解析）
   - `pushBusinessDiff(userId, changed)` → user-update-info，只推变化字段；`logoSrc`/`qrcodeSrc` 仅 http(s) URL 才推
   - `uploadUserImage(userId, imageType, src)`：H5 dataURL 直接传；weapp 临时文件 `Taro.getFileSystemManager().readFile` 转 base64 → user-update-image-qiniu → 返回 `{url}`
3. **`wechat-mini/src/services/user.ts`**：增加 `sendSms(phone)`、`registerOrLogin(phone, code)`（走 user-register）；现有 wxLogin/loginWithPassword 依赖 cloud.ts 归一化后自然可用
4. **`wechat-mini/src/types/user.ts`**：`MiniUser` 扩展 `phone?`/`hasPassword?`/`vipValidUntil?`/`brandname?`/`promoText?`/`logoUrl?`/`qrcodeUrl?`

### C. 登录页 `wechat-mini/src/pages/login/index.tsx`

- 增加「短信登录/注册」tab：手机号 + 验证码输入 + 发送按钮（60s 倒计时），调 send-sms + user-register
- 三种方式并列：微信一键登录 / 账号密码登录 / 短信验证码登录（未注册自动注册，与网页一致）

### D. 编辑器接线 `wechat-mini/src/pages/editor/index.tsx`

1. **登录后拉取**：监听 user store `userId` 出现 → `pullBusinessInfo` → 覆盖 `business`（云端优先，与网页 `syncAndFillBusinessInfo` 行为一致）→ 写 `lastSyncedRef` 快照
2. **编辑后推送**：`business` 变化 useEffect → 防抖 1.5s → 与 `lastSyncedRef` diff → `pushBusinessDiff`（仅登录态；成功后更新快照）
3. **图片上传**：logo/二维码确认落位时（confirmLogoEdit、二维码确定），若已登录且 src 非远程 URL → `uploadUserImage` 换 URL 写入 business（上传失败不阻断，保留本地可重试）
4. 未登录：行为不变（纯本地），登录后自动接管同步

### E. 我的页 `wechat-mini/src/pages/mine/index.tsx`

- 显示手机号（脱敏）/VIP 到期时间/云端同步状态；退出登录清 user store（business 本地保留）

## 复用清单

- 网页同步流程照搬 `cloud-sync.js`（字段单独 diff 推送、登录后云端覆盖本地）
- 云函数双格式输入兼容已现成，只需小程序端归一化输出
- 登录页 UI/密码登录服务/`wx-login` 云函数骨架已存在，补齐即可

## 明确不做

- 微信支付/VIP 购买（`vpay-sign` 仍占位）
- 头像 `avatar` 的采集与展示（users.avatar 字段保留透传，海报数据以 logoUrl 为准）
- 网页端代码改动（其同步逻辑已完整，仅共享云函数向后兼容扩展）
